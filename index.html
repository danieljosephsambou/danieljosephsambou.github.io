01 — Approche

Le code livré, pas juste imaginé.

— A

Du métier au modèle

Je pars des règles réelles — un article du code du travail sénégalais, une exemption fiscale camerounaise, une règle physique de compteur — avant d'écrire une seule ligne. Le modèle sert la règle, jamais l'inverse.

— B

Full-stack pragmatique

FastAPI côté serveur, React/TypeScript/Vite côté client, SQL là où les données vivent. Une stack que je maîtrise assez pour livrer vite et corriger un bug sans devoir tout redessiner.

— C

Lisible et documenté

Une formule de paie, une API de fraude ou un labo de maths se relit six mois plus tard. Nommage explicite, décisions consignées, cas limites énoncés — c'est ce qui distingue un prototype d'un outil qui tourne.
